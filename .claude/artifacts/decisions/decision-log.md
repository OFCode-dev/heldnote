# Decision Log

| Date | Decision | Why | Tradeoff |
| --- | --- | --- | --- |
| 2026-08-05 | Start a new project rather than version 3 of `quick-web-notepad` | Multi-note storage and version history change the data model and the UI shape enough that they are a different product, not a bigger notepad | The old project's single-file convenience is lost; two repos to maintain |
| 2026-08-05 | Persist to IndexedDB, no backend | Works on GitHub Pages with no server cost, and holds far more than localStorage without blocking the main thread | Data lives in one browser profile until sync ships |
| 2026-08-05 | Two persistence layers: per-keystroke draft plus committed snapshots | Never-lose and go-back are different guarantees; separating them keeps the never-lose path free of any computation that could fail | One more store, and a note's newest text lives in two places at once |
| 2026-08-05 | Store versions as full snapshots, not diffs | Restoring is a read rather than a computation, so history cannot silently drift; briefly reversed to diffs mid-design, then reverted | Uses more disk than a diff log; requires a pruning ladder to stay bounded |
| 2026-08-05 | Fresh codebase of small ES modules, no build step | The old single file had grown to 1628 lines with unrelated pasted CSS; multi-note plus history needs real boundaries | Editor features must be ported over deliberately rather than inherited |
| 2026-08-05 | Ship v1 without sync, but write sync-shaped fields now | Gets a working app soonest while keeping `id`, `updatedAt`, `deletedAt`, `rev` available for Drive sync in v2 | Carries fields nothing reads yet |
| 2026-08-05 | Keep two documentation homes | User chose both the artifacts tree and the superpowers spec | Same content in two places; the spec is canonical and the artifacts must follow it |
| 2026-08-06 | Store `isDeleted`/`pinKey` as 0\|1 and omit `deletedAt` while live | Booleans and null are not valid IndexedDB keys, and an invalid indexed value is silently omitted from the index — the original schema would have returned an empty note list while every note sat intact | Stored shape differs from the domain shape; `store.js` normalizes at the boundary |
| 2026-08-06 | Order by `localRev`, not by timestamp | A timestamp stamped at enqueue time can be older than a version committed while the write was in flight, which would hide a successfully stored draft; clocks also move backwards | One more field to maintain and assert |
| 2026-08-06 | Make restore a single fenced transaction with a pre-restore checkpoint | Restoring while the current text was drafted but never versioned destroyed it, and the duplicate check then suppressed the commit meant to make the restore undoable | One extra snapshot per restore, and stricter write queueing |
| 2026-08-06 | Replace the 1 s max-wait with a coalescing writer bounded at 300 ms to transaction completion | The max-wait contradicted the durability window it was added to protect | Roughly three to four writes per second while typing, costing battery and I/O |
| 2026-08-06 | Use Web Locks — per-note for editing, one global for maintenance | A BroadcastChannel heartbeat is a message bus, not a lock, and its races let two tabs both write; a crashed tab's context releases a Web Lock automatically | Per-note locking is slightly more bookkeeping than a single global writer lock, and keeps two notes editable in two tabs |
| 2026-08-06 | Report retention as a state, separate from save status | Durability of a revision and retention by the browser are different claims; merging them into one green light would be the product's central lie | The interface must explain two things instead of one |
| 2026-08-06 | Declare ordinary Safari non-durable | WebKit's seven-day cap applies without qualifying interaction and `persist()` is not understood to exempt it; Private Browsing passes a write probe while being session-only | The promise is narrower on Safari, stated openly rather than discovered by a user |
| 2026-08-06 | Require a dedicated immutable origin | IndexedDB is scoped by origin, so every repository under a shared `owner.github.io` host can read and delete this database, and any origin change orphans existing notes | Deployment rigidity; the host can never change casually |
| 2026-08-06 | Bound storage by bytes, not record counts | Record counts bound nothing while note size is unbounded; the old 5 MB target, the unlimited note size, and the ADR's own 10 MB example could not all be true | A maximum note size must exist and be measured |
| 2026-08-06 | Cut semantic merge on import, keep replace and import-as-copies | `[noteId, seq]` collides across divergent branches, so a merge cannot honour "nothing is discarded silently" | Duplicate notes after some imports, which is the safer failure |
| 2026-08-06 | Remove automatic trash purge | Timed deletion of the only remaining copy is the wrong default for this product, and a clock jump could fire it early | Trash grows until the user empties it |
